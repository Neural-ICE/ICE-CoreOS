# ADR-0042 — Qualifier NVIDIA R580.159.03 sur GB10

- **Status**: Accepted for experimental/beta qualification
- **Date**: 2026-07-29
- **Decider**: Business/Security Owner (human)
- **Scope**: NVIDIA driver generation only; kernel source, 4 KiB page size,
  Secure Boot policy and stable channel remain unchanged

## Context

The live DGX Spark appliance runs the GB10 4 KiB CentOS Stream 10 kernel with
NVIDIA R595.58.03. During the 2026-07-29 demo incident, GPU workloads retained
unified memory after completion. A global `drop_caches=3` timer had been added
as a mitigation, but it invalidated hot application data every two minutes:

- the Swiss Case Law mission started at 08:51:34;
- global cache drops occurred at 08:51:47 and 08:53:50;
- two `caselaw_search` calls reached their 60-second timeout;
- once hot and undisturbed, the same service answered in 0.35–5.3 seconds and
  decision detail in 9 milliseconds.

A separate THP compaction issue was isolated with an A/B test: before
`transparent_hugepage/defrag=never`, the host scanned 5.15 million pages/s,
stalled 82 times/s and left the GPU idle; after the change, compaction scans and
stalls fell to zero and the GPU reached 94%. That tuning must remain independent
from the driver experiment.

NVIDIA's DGX Spark guidance moved the supported branch back to R580.159.03.
CUDA 13.x supports R580 through minor-version compatibility, subject to the
usual limitation that applications requiring a newer driver feature must fail
qualification rather than silently fall back.

## Decision

Build an **experimental/beta-only** ICE-CoreOS generation with NVIDIA
**580.159.03** and retain the last finalized R595.58.03 generation as the
immediate rollback target.

The generation is valid only if all NVIDIA components originate from the same
official extracted runfile:

- `kernel-open` source compiled against the exact GB10 kernel;
- `libcuda`, NVML, CFG and PTX JIT userspace libraries;
- `nvidia-smi`, `nvidia-modprobe` and `nvidia-persistenced`;
- `gsp_ga10x.bin` and `gsp_tu10x.bin`.

The workflow stages that version-matched payload into a run-scoped directory.
The image build derives `NVIDIA_DRIVER_VERSION` from the verified finalized
generation; a mutable shared userspace directory is no longer accepted.

The existing Owner-controlled Secure Boot finalization remains fail-closed.
This decision does not change keys, signer mappings, boot policy, kernel source,
page size, production channel or anti-rollback rules.

## Qualification gates

R580.159.03 may enter beta only after:

1. candidate provenance and hashes verify;
2. signed boot finalization binds the exact candidate vmlinuz;
3. `getconf PAGESIZE` reports 4096;
4. `modinfo nvidia`, `nvidia-smi` and CDI report 580.159.03 consistently;
5. vLLM, embeddings, reranking and both Paddle workers start and pass health;
6. a warm 10-page PDF and a larger batched PDF complete OCR + RAG;
7. repeated allocate/infer/free cycles release unified memory without a global
   cache drop;
8. Case Law warm search remains below its 60-second tool timeout;
9. a reboot preserves GPU, GSP/initramfs, CDI and workload health;
10. `bootc rollback` remains available to the retained R595 deployment.

Stable is explicitly out of scope until those gates pass.

## Rollback

Before image construction, restore the retained, verified artifact generation:

```sh
ARTIFACTS_ROOT="$HOME/neural-ice/artifacts" \
  ./ci/artifact-generation.sh activate <r595-generation-id>
```

On a beta appliance with the previous deployment retained:

```sh
sudo bootc rollback
sudo systemctl reboot
```

Rollback verification repeats page-size, GSP, `nvidia-smi`, CDI and workload
health checks. Do not delete the R595 generation or deployment during R580
qualification.

## Consequences

- (+) Tests the currently supported DGX Spark driver branch without changing
  the rest of the appliance stack.
- (+) Removes the latent module/userspace/firmware version-mixing hazard.
- (+) Preserves a verified R595 rollback.
- (-) CUDA minor-version compatibility does not guarantee every CUDA 13.x
  feature; full workload qualification is mandatory.
- (-) The Red Hat GB10 kernel remains Developer Preview.
